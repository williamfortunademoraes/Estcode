# ESTCODE 2.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox syntax for tracking.

**Goal:** Deliver profile and product improvements, expanded persisted stock preferences, and a secure direct NF-e distribution workflow with reviewed, idempotent stock entry.

**Architecture:** Keep the Expo client limited to authenticated UI and calls to Supabase plus a protected Node fiscal API. The API validates Supabase JWT/profile role and uses a host secret for the A1 PFX while connecting to official NF-e distribution over mutual TLS. Persist documents and NSU checkpoints with database uniqueness; route all inventory effects through server validation and transactional RPCs.

**Tech Stack:** Expo SDK 58, React Native, TypeScript, Expo Router, React Native Paper, React Hook Form, Zod, Zustand, Supabase/PostgreSQL/RLS/RPC, Node.js HTTPS fiscal API, Jest/RNTL.

**Spec:** `docs/superpowers/specs/2026-11-19-estcode-v2-design.md`

## Global Constraints

- Never put the A1 certificate or its password in the mobile application, ordinary database columns, logs, source control, or build artifacts.
- Query the official recipient distribution service by persisted NSU; respect official response codes and minimum wait windows.
- Never create stock movements until a permitted user reviews and confirms an invoice.
- Enforce permissions in PostgreSQL/server functions as well as the UI.
- Use idempotency for distribution records and stock application.
- Do not add settings without an explicit operational meaning and persisted rule.
- Preserve Expo SDK 58 compatibility and use `npx expo install` for native dependencies.

## Review Focus

- Missing/invalid certificate or wrong company CNPJ: reject setup/consultation safely; pin with configuration and service tests.
- `cStat=137`, throttling window, or SEFAZ outage: preserve checkpoint and show actionable state; pin in distribution adapter tests.
- Duplicate NSU/access key or repeated confirmation: no duplicate document or balance; pin with database integration tests.
- Summary-only invoice, canceled invoice, and invoice event: do not treat as applicable complete XML; pin with parser and workflow tests.
- Product association/unit mismatch or restricted role: block application and explain required correction; pin in service/RPC and permission tests.

- Modify `src/app/(tabs)/products.tsx` and product display components/permissions for price visibility and thumbnails; split `/products/[id]` into a read-only product detail route and a separate edit route; add product image upload/storage reference.

- Add a protected fiscal API under `services/nfe-api/`; it must validate bearer JWT with Supabase, check active admin profile, use only user-scoped Supabase access for data writes, and read A1 PFX/password from hosting secrets.
